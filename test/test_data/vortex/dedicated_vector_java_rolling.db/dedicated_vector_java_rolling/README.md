# Java Dedicated VECTOR Independent Rolling Fixture

This table was generated on 2026-10-19 using the Paimon Java batch write API.
It contains one Parquet main file and four independently rolled Vortex VECTOR
files from one APPEND commit. Java read back and checked every row and the
file metadata before the table files were copied here without modification.
The fixture exercises C++ reads when main and VECTOR file row ranges differ.

Writer provenance:

- Apache Paimon Java `2.2-SNAPSHOT`, source commit
  [`7d6d146bbaf33a349dc83c3caf71334bd551e3d5`](https://github.com/apache/paimon/commit/7d6d146bbaf33a349dc83c3caf71334bd551e3d5).
- Vortex native library `dev.vortex:vortex-jni:0.73.0` and Arrow Java `15.0.0`,
  selected by that source revision.
- Amazon Corretto JDK `17.0.20.1` (`17.0.20.12.1`), Maven `3.9.16`,
  macOS `15.5`, `aarch64`.
- `GenerateDedicatedVectorRollingFixture.java` is the generator used for this
  table. `pom.xml` supplies the runtime dependencies after building the pinned
  Java revision.

Schema (all three columns are nullable):

```text
id INT
embedding VECTOR<FLOAT, 3>
tag STRING
```

The 3,001 rows have `id` values from 0 through 3,000. For each row, `tag` is
`row-<id>` and `embedding` is `[id, id + 1, id + 2]` as FLOAT values, except
for NULL vectors at ids 0, 999, 1000, 1999, 2000, 2999, and 3000. These NULL
values cover both sides of the VECTOR file boundaries; the last VECTOR file
contains one NULL vector.

Options:

```text
file.format = parquet
vector.file.format = vortex
bucket = -1
row-tracking.enabled = true
data-evolution.enabled = true
write-only = true
target-file-size = 128 mb
vector.target-file-size = 1 kb
write.batch-size = 100
read.batch-size = 127
```

`write-only` prevents background compaction. The small writer batch ensures
Vortex flushes buffered data before Java checks the rolling condition at
1,000-row intervals. Java's Vortex writer estimates compressed size from
flushed Arrow buffers, so `vector.target-file-size` is a rolling target,
not a hard limit on the physical file size. The main file remains open while
the VECTOR files roll. The read batch size does not divide any 1,000-row
VECTOR file, exercising alignment between reader batches near file boundaries.

were generated by Java together with the data files.

## Reproduce

Run from the Paimon C++ repository root with JDK 17 and Maven available.
The commands generate a new temporary warehouse and leave this fixture
untouched.

```bash
fixture_dir="$PWD/test/test_data/vortex/dedicated_vector_java_rolling.db/dedicated_vector_java_rolling"
generation_dir="$(mktemp -d)"
git clone https://github.com/apache/paimon.git "$generation_dir/paimon"
git -C "$generation_dir/paimon" checkout 7d6d146bbaf33a349dc83c3caf71334bd551e3d5

mvn -B -ntp -f "$generation_dir/paimon/pom.xml" \
    -pl paimon-vortex/paimon-vortex-format -am \
    -DskipTests -Dcheckstyle.skip -Dspotless.check.skip \
    -Drat.skip=true -Dlicense.skip=true install

mvn -B -ntp -f "$fixture_dir/pom.xml" \
    org.apache.maven.plugins:maven-dependency-plugin:3.6.1:build-classpath \
    -Dmdep.outputFile="$generation_dir/classpath.txt"

java --add-opens=java.base/java.nio=ALL-UNNAMED \
    --class-path "$(cat "$generation_dir/classpath.txt")" \
    "$fixture_dir/GenerateDedicatedVectorRollingFixture.java" \
    "$generation_dir/warehouse"
```

The Arrow Java memory implementation requires `--add-opens`. The generator
asserts every row value and NULL vector, all 3,001 distinct ids, one main file,
and the four VECTOR file ranges. A successful run prints
`Java readback verified: 3001 rows`, followed by the five metadata records,
and exits with code zero.

The generated table is under
`$generation_dir/warehouse/dedicated_vector_java_rolling.db/dedicated_vector_java_rolling/`.
UUIDs, timestamps, and commit users change on regeneration; row values and
row-range relationships remain the same.
